# manual/ — 人手維護嘅數據

> 呢份係**年度維護清單**。半年後要更新數據,睇返呢份就夠,唔使睇 code。
> 規則(SPEC 第 6 節):**唔好寫 PDF parser,一律人手抄一次。** 自動化 PDF 解析嘅維護成本會爆。
> 規則(SPEC 第 7 節):GitHub Actions **永遠唔碰** 呢個目錄。呢度嘅檔只有你會改。

## 點運作

1. 每個檔係一個指標,格式同自動抓嘅完全一樣(SPEC 第 5 節 schema),只係 `"acquisition": "manual"`。
2. `src/data/<id>.json.js` 會讀呢度嘅 JSON,驗 schema,再同自動抓嘅一視同仁咁出到網站。
3. **數值填 `null` 就係「未填」**。全部 `null` 嘅指標:網站會 build 到,但首頁唔會出佢張卡,頁面會顯示「數據未填」。
   咁做係跟 SPEC 第 2 節第 4 條:「唔准估數……寧願個指標唔出現。」
4. 填完之後跑 `npm run build`,首頁張卡自動出現。`npm run validate` 會幫你驗 schema。
5. `_` 開頭嘅欄位(例如 `_maintainer_notes`)係畀你自己寫筆記用,唔會出到網站。

## 每個檔要抄乜、去邊度抄、幾時抄

### `phr_waiting_time.json` — 公屋輪候時間

| | |
|---|---|
| 去邊度抄 | https://www.hb.gov.hk/tc/publications/housing/cwt/index.html(**房屋局**,唔係房委會 —— 房委會嗰版而家只係轉介)|
| 幾時更新 | **每季**。房屋局每季公布一次,通常喺季尾之後一個月內 |
| 抄邊幾個數 | 一般申請者嘅「綜合輪候時間」(CWT,含簡約公屋)、一般申請者嘅「平均輪候時間」(AWT,只計傳統公屋)、長者一人申請者嘅平均輪候時間 |
| 期數點寫 | 網頁寫「截至 YYYY 年 M 月底」→ `period` 用季度寫法,例如 6 月底 = `"2026-Q2"`,9 月底 = `"2026-Q3"` |
| 單位 | 年(可以有一位小數,例如 `4.8`)|

**⚠️ 兩個數字定義唔同,唔可以撈亂:**
- **CWT(綜合輪候時間)** 計埋簡約公屋,數字細啲
- **AWT(平均輪候時間)** 只計傳統公屋,數字大啲

兩個都要抄,`category` 要寫清楚係邊個。畫面會兩條線並列顯示,由學生自己睇分別。

> 探路嗰陣(2026-09-04)喺網頁讀到:截至 2026 年 6 月底,CWT 4.8 年、AWT 5.5 年。
> **呢兩個數係 AI 探路員讀返嚟嘅,未經你核對,所以 JSON 入面照樣留 null。** 你開返嗰版對一對再填。

**歷史數列**:live 頁面只有最新一季。想要成條線就要開房屋局嘅季度 PDF 逐季抄,
一年抄 4 個數,成本可以接受。抄一季加一個 `period`。

**授權**:hb.gov.hk **冇**開放數據授權頁,係全站 13 個來源入面授權最弱嗰個。
JSON 入面 `licence` 暫時寫「房屋局網頁,一般政府網站版權告示」。畫面會照樣顯示來源連結。

### `govt_expenditure_policy_groups.json` — 政府開支(十個政策組別)

| | |
|---|---|
| 去邊度抄 | 財政預算案「附錄 B」PDF:`https://www.budget.gov.hk/{YYYY}/chi/pdf/c_appendices_b.pdf`,`{YYYY}` 係預算案年份(例如 2026 = 2026-27 年度預算案)|
| 幾時更新 | **每年一次**,2 月尾預算案發表之後 |
| 抄邊幾版 | 第 II 部「經常開支」(page 7–8)同第 III 部「開支總額」(page 9–10)。第 VII 部(page 17)有政策組別嘅分類定義 |
| 每份 PDF 有幾多年 | 得 3 個年度:上年度**實際**、本年度**修訂預算**、下年度**預算**。想要長數列就逐年開舊 PDF(2016 至 2026 都仲喺度)|
| 單位 | PDF 寫「百萬元」。**JSON 入面照抄百萬元嘅數字**(例如 `102308`),唔好自己乘,loader 會換算 |

**⚠️ 口徑陷阱(對「分餅」活動致命):**
附錄 B 每個組別都出**兩套數**:
- **政府開支**(Government expenditure)—— 只計政府帳目
- **公共開支**(Public expenditure)—— 包埋房委會等營運基金同法定機構

兩者可以差好遠:2026-27 房屋一項,政府口徑 1,226 百萬 vs 公共口徑 22,635 百萬,**差 18 倍**。
揀錯會令學生以為政府幾乎冇使錢喺房屋。

呢個檔**用「政府經常開支」口徑**(`basis_zh` 欄寫死咗),同自動抓嗰個 `govt_expenditure` 指標嘅總額對得返。
想加公共口徑就另開一個檔 `govt_expenditure_policy_groups_public.json`,唔好溝喺同一個檔。

**自我核對**:抄完之後,十個組別相加應該等於 PDF 自己寫嘅總額(2026-27 政府經常開支總額係 599,677 百萬)。
對唔上就係抄錯咗一個。`npm run build` 會幫你驗呢條數,對唔上會 fail。

**組別名稱**:JSON 入面預填咗十個組別名,請對返 PDF 第 VII 部,唔啱就改。

**授權**:budget.gov.hk 嘅版權告示(`https://www.budget.gov.hk/2026/chi/important.html`)**窄過** data.gov.hk:
只准個人參考或教育用途,複製本不能轉售。本專案係教育用途,符合。

## 抄完之後

```bash
npm run validate     # 驗 schema、驗組別相加等於總額
npm run build        # 首頁張卡會自動出現
git add manual/ src/data/_snapshots/
git commit -m "人手更新:<邊個指標> <期數>"
```

## 年度節奏(建議)

| 月份 | 做乜 |
|---|---|
| 3 月 | 預算案出咗:抄 `govt_expenditure_policy_groups`(3 個年度)|
| 每季(1、4、7、10 月)| 房屋局出咗新一季:抄 `phr_waiting_time` 一個期數 |

大部分指標一年更新一次就夠。唔好追每月數 —— 追唔切反而令個站長期顯示「數據截至」好耐之前。
