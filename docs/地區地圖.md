# 十八區與代表景點地圖

新增資料模組為 `src/components/hong-kong-districts.js`、`src/components/hong-kong-attractions.js`。
兩者均為隨站發佈的純資料，沒有地圖 SDK、圖磚、瀏覽器外部請求或定時定位工作。
既有 `src/assets/hong-kong-map.svg` 保持原樣，來源及製法見[地圖來源.md](地圖來源.md)。
本輪增加獨立的十八區圖層，只有取得相應整區統計時才將統計數值連到區碼。

## 來源、年代與重用

| 部分 | 官方來源 | 本次資料 |
|---|---|---|
| 十八區分界 | [民政事務總署行政區界線（CSDI）](https://portal.csdi.gov.hk/csdi-webpage/dataset/had_rcd_1634523272907_75218) | 2026-09-09 取得；18 個 `DCD`，`BEGIN_LIFESPAN` 全為 2016-01-01，`END_LIFESPAN` 為空 |
| 陸地輪廓 | [地政總署香港 1:50 000 地形圖](https://portal.csdi.gov.hk/csdi-webpage/dataset/landsd_rcd_1637221775627_85634) | 重用 2026-09-08 製作原地圖時，由特區範圍扣除海面而得的陸地幾何 |
| 景點定位 | [地政總署 Location Search API 文件](https://portal.csdi.gov.hk/csdi-webpage/apidoc/LocationSearchAPI) | 2026-09-09 逐筆查詢、核對名稱／地址／HK80 坐標／區名，再對 HAD polygon 核對所屬區 |
| 景點簡介 | [香港旅遊發展局景點介紹](https://www.discoverhongkong.com/tc/attractions.html) | 2026-09-09 查核；每個景點保留直接來源連結，以短句改寫事實；課堂問題由本站編寫 |

`verified_at` 是本站核對日期，**不是邊界生效日期、測量日期或人口統計年份**。
圖層使用十八個行政區，並非 2023 年的四十四個區議會地方選區；全港參考值也不是第十九區。
人口／入息的統計期由相關指標資料指定，不能用地圖日期取代。今次沒有從簡化圖形計算人口密度。

政府空間資料按 [CSDI 使用條款](https://portal.csdi.gov.hk/csdi-webpage/doc/TNC)
及相關 [DATA.GOV.HK 使用條款](https://data.gov.hk/tc/terms-and-conditions) 重用。
CSDI 條款涵蓋 API 資料，允許下載、複製及分發，並要求來源及知識產權鳴謝；重用須遵守完整條款。
模組保留授權連結及以下鳴謝，頁面亦需顯示來源：

> © 香港特別行政區政府；民政事務總署及地政總署，經空間數據共享平台提供。

景點介紹只連結及短述官方事實，沒有複製旅發局圖片、地圖、宣傳全文、票價或開放時間。
代表景點由本站為課堂挑選，**並非官方排名、旅客人次排名或完整名錄**。

## 十八區製作方法

官方服務為 `https://portal.csdi.gov.hk/server/rest/services/common/had_rcd_1634523272907_75218/MapServer`。
查閱服務及 `0` 圖層元資料後，確認 `DCD`、polygon、香港 1980 方格網，再取得：

```sh
curl --fail --get \
  'https://portal.csdi.gov.hk/server/rest/services/common/had_rcd_1634523272907_75218/MapServer/0/query' \
  --data-urlencode 'where=1=1' \
  --data-urlencode 'outFields=*' \
  --data-urlencode 'outSR=2326' \
  --data-urlencode 'f=json' \
  --output had-districts.json
```

原始回傳完整保存為 `scripts/fixtures/geography/had-districts-2026-09-09.json.gz`，
解壓 SHA-256 為 `db78a66409449135e3e117a9cc037ed8f13313eefd86b6b1dff19e4ca4e5fc8a`。
`AREA_ID` 直接作本站 `id`，`NAME_TC` 直接作中文區名；
`AREA_CODE` 另存為 `had_code`，`CSDI_ADMIN_AREA_ID` 存為 `source_id`。沒有按名稱猜區或按字母重新排序。

| 碼 | 區名 | 碼 | 區名 | 碼 | 區名 |
|---|---|---|---|---|---|
| A | 中西區 | G | 九龍城區 | M | 元朗區 |
| B | 灣仔區 | H | 黃大仙區 | N | 北區 |
| C | 東區 | J | 觀塘區 | P | 大埔區 |
| D | 南區 | S | 葵青區 | R | 沙田區 |
| E | 油尖旺區 | K | 荃灣區 | Q | 西貢區 |
| F | 深水埗區 | L | 屯門區 | T | 離島區 |

處理僅執行一次，使用臨時環境 Shapely 2.1.2／GEOS 3.13.1，沒有新增專案依賴：

1. 確認官方回傳無錯誤、無截斷，18 個原始區 polygon 全部有效且構成有效 coverage。
2. 用既有地政署陸地幾何與各原始區相交，避免把水面畫成統計色塊。
3. 對十八區**一起**執行 `coverage_simplify(clipped, 25)`，容差單位為 HK80 米。
   這是保留共享邊界的簡化；沒有將相鄰區各自簡化而造成縫隙或重疊。
4. 再確認每區非空、polygon 有效、整組 coverage 有效。保存所有外環及內環，轉為 SVG 的 `M/L/Z` 路徑。
   畫面必須採用 `fill-rule="evenodd"`，保留島嶼間空白及內洞。
5. 每區的文字定位取**最大陸地 polygon 的內部代表點**，再核對位於原始所屬區及簡化陸地內。
   `anchor_kind: "land-representative-point"` 明示這是顯示用途，並非官方地理中心或人口重心；沒有用可能落海的 bounding box 中心。

裁剪材料 `landsd-land-2026-09-08.geojson.gz` 是先前由政府海面及特區界線**推導**的 GeoJSON，
不是政府直接提供的名為「香港陸地」的檔案。解壓 SHA-256 為
`dbd71908cc4385f56d37717b13d03c327b19b8e7c61012e1beacc266bd997230`。
海岸與行政區分界屬不同來源；落在陸地輪廓內但不屬任一原始區 polygon 的部分保留底圖顏色，沒有就近硬塞入某區。
本地圖用於區域定位與比較，不能作土地測量、規劃界線裁定或推算面積的工具。

## 坐標與量度自證

HK80 原始坐標順序是東距 `E`、北距 `N`，單位米，沒有假設 GPS 經緯度的 datum。
兩個新圖層與既有 `viewBox="0 0 900 560"` 完全使用同一仿射變換，輸出保留小數點後兩位：

```text
x = (E - 832250) × 0.0112 + 450
y = (824000 - N) × 0.0112 + 280
```

在首次生成／量度前，已用以下獨立已知答案自證，回歸測試每次亦先驗這四項：

| 東距 | 北距 | SVG x | SVG y |
|---:|---:|---:|---:|
| 832250 | 824000 | 450 | 280 |
| 797000 | 849000 | 55.2 | 0 |
| 867500 | 799000 | 844.8 | 560 |
| 837250 | 824000 | 506 | 280 |

製作工具先通過四個幾何答案：2×2 方形面積 4、4×4 方形扣去中央 2×2 方洞後面積 12、
兩個重疊 2×2 方形的聯集面積 6，以及相鄰兩個單位方形在 coverage 簡化後仍等於 2×1 長方形。
另外先驗方形內外／邊界及方洞的 point-in-polygon，才用它核對景點所屬區。
這些答案不由本次香港資料或輸出圖形倒算。

## 景點定位選擇

查詢實際 endpoint 為 `https://www.map.gov.hk/gs/api/v1.0.0/locationSearch`，參數為 `q`；
例如 `curl --fail --get 'https://www.map.gov.hk/gs/api/v1.0.0/locationSearch' --data-urlencode 'q=天壇大佛'`。
這些請求只於人工製作及核查資料時執行，正常 build／測試／瀏覽均不打 API。

官方搜尋可能同時回傳地名、建築、設施、商戶、停車場及同名不同位置；沒有「取第一項」的自動規則。
每一項都按實際回傳逐筆選定以下位置，另對 HAD 原始十八區 polygon 做空間核對。

## 防錯與更新

`scripts/test-district-geography.mjs` 直接 import production exports，包含 62 項檢查：
換算及幾何工具先自證；原始 fixture／控制材料的 SHA-256 釘死；逐區比對官方區碼、中文名及 CSDI ID；
逐點比對官方坐標、名稱、地址及區名；逐一以原始 polygon 核對景點所屬區；驗證文字錨點在區內，
以及保存完整已驗路徑的 hash、島嶼／內洞數量。這套 Node 回歸測試不依賴 Shapely 或網絡。

自證包括故意換成鄰區形狀、對調區名、把文字移到海上、刪小島、漏區、重複 ID、
調轉景點 XY、錯配所屬區、換合法分類、同名商戶冒充景點、刪來源、刪定位說明及刪版權鳴謝。
另外建立 production 模組的臨時副本，實際改壞區名、景點 x 軸、分類及來源，再 import 後由同一檢查器捉錯。

`district-controls.json` 記錄本次有效 coverage 輸出的路徑 hash 及內部代表點。
它自身也有固定 hash，不能透過同步改壞 fixture 或 expected 令檢查假綠。
若官方邊界真的更新，須重新核對來源及有效期、重跑已知答案及 coverage 檢查、檢視圖形，
才一併更新 fixture／production／控制 hash／這份文件，不能單改 hash 壓下失敗。

顏色只能表示**整區**人口／入息統計；同一區內居民、住宅、商業、山地及景點並不均勻。
住戶入息中位數也不是個人收入、平均收入、資產或個人財富；景點不具有該區中位數所代表的收入。

## 選區概況、歷史與景點搜尋

`district-explorer.js` 在原有地圖下加入 `district-profile.js`，可選共同年度、香港地區、
對照地區或全港，以及所選年或之前的變化基期。人口與住戶入息的原值、差額、百分比、
兩幅獨立歷史圖及原始表共用 `district-history.js` 模型；每幅圖的兩條地區線共用零起點刻度，
人口與入息唔共用 Y 軸。缺值及缺年斷線，唔用最近有值年度補位。

人口比例＝該地區人數 ÷ 同表同年度全港陸上非住院人口 × 100，頁面列出分母。
全港入息中位數直接讀官方全港分類，唔平均各區中位數。入息差額與百分比係名義變化，未扣通脹；
零基期唔計百分比。`test-district-history.mjs` 對比例、正負及零變化、歷史圖幾何先用已知答案自證，
再測無效分類／年度／數值，以及真正 production helper 的源碼突變。

概況附來源、統計期、版本與可選取引用，並連到青年預算備忘工作紙。
「列印區情簡報」使用瀏覽器列印；列印前展開概況的歷史及引用，列印後還原摺疊狀態。
同一安排支援瀏覽器原生列印入口，頁面撤銷時移除相關事件監聽；唔開新報告服務或儲存使用者資料。

旅遊圖層沿用上述十個已核代表景點，加文字搜尋及類別選擇。
地圖標記與景點清單讀同一份篩選結果，清除條件可回到全部景點；編號保持原有選錄順序，唔係排名。
零結果時明示「未收錄相符地點」，唔把未收錄解釋成區內冇文化或旅遊設施。
本輪介面功能借鏡與範圍見[城市觀察參考](./城市觀察參考.md)。
