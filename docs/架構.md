# 三層防護 — 邊層防乜

呢個站有三層互相**唔重疊**嘅防護。三層防唔同嘢、喺唔同時候跑、失效方式亦唔同。
混淆咗就會出現「以為驗過,其實冇」。

| 層 | 防乜 | 幾時跑 | 失效之後會點 |
|---|---|---|---|
| **Fixture 重播** | **程式碼**回歸 —— 改壞 transform | 每次 `test:checks`,零網絡 | 改壞咗嘅計算靜靜哋出街 |
| **不變式檢查**<br>(人口 pin、分類相加) | **上游數據**漂移 —— 來源改結構／改口徑 | 每次真實重抓 | 用錯咗嘅行／欄冒充正確數字 |
| **Fail-soft** | **可用性** —— 上游暫時掛咗 | 每次真實重抓 | 個站變空白,或者出空陣列 |

## ⚠️ Fixture **唔**保護上游漂移

呢點唔寫低,遲早有人以為 fixture 綠燈就代表數據啱。

錄影同快照係**一齊更新**嘅(`npm run refresh` 一次過做兩樣)。所以上游改咗結構,
錄影同快照會一齊郁,重播照樣對得上 —— **綠燈,但個數可能已經錯咗**。

抵擋上游漂移嘅係**不變式檢查**,而佢哋只喺真實重抓嗰陣先跑得到:

- 人口:抽出嚟每一點都要等於嗰期「男 + 女」相加
- FSTB / manual:分類相加要等於來源自己印嘅總額
- 統計處:每個 cv code 都要對返 `table_<id>_lang.json` 存唔存在

## 合規唔等於數啱

Schema 驗證只答「格式啱唔啱」,唔答「個數啱唔啱」。

實測過三個突變:

| 突變 | schema | 對數 |
|---|---|---|
| loader 寫漏 `source_url` | ✗ 捉到 | ✗ 捉到 |
| 人口換算 ×1000 → ×1001 | **✓ 過到** | ✗ 捉到 |
| 失業率 `pin` 由 Total 改成男性 | **✓ 過到** | ✗ 捉到 |

後兩個 schema 完全過到,靠「重播結果嘅 `content_hash` 對返已 commit 嘅快照」先捉到。
所以 `test:checks` 嘅 R5 一定要同時做兩樣:驗 schema **同埋**對數。

## Fail-soft 只覆蓋「攞唔到數」

用 error **類型**分,唔用 message 分(message 係畀人睇嘅,改文案唔應該改變行為)。

```
UpstreamError  網絡去唔到 / HTTP 唔 ok / 回應唔係 JSON / 上游格式變
               -> fail-soft:保留上一版,build 照樣成功,Actions summary 標紅

其餘一切       schema 錯 / cv code 錯 / 換算錯 / 登記冊打錯字
               -> hard fail:下星期再抓一萬次都一樣錯
```

呢個係**白名單**唔係黑名單:新加嘅錯誤類型預設 hard fail,唔會靜靜哋被吞。

## 6 日新鮮期 — 三道閘一齊擋

快照有 6 日新鮮期,期間 `observable build` **完全唔會執行 loader**;
CI 部署用 `HKDM_OFFLINE=1`,更加永遠唔會執行。所以「改壞咗 transform」
單靠 build 係捉唔到嘅 —— 實測過 loader 寫漏 `source_url`,build 綠燈,出緊舊快照。

1. `build` 開頭 `npm run validate` —— 驗現有快照同 `manual/`(零網絡)
2. `test:checks` 用錄影重播完整 transform,再對返快照(零網絡、0.2 秒、11 個指標)
3. schema 錯誤 hard fail,唔行 fail-soft

## 錄影同快照要原子更新

一個指標唔止打一個 endpoint:

| 來源 | 每個指標打幾多個 |
|---|---|
| 統計處 | **3**(`comp.json` + `lang.json` + POST) |
| 庫務署(財政儲備) | **8**(每個財政年度一份檔) |
| FSTB | 1 |

錄影做喺 HTTP 層,所以「頭幾個成功、最後一個 404」嗰陣,成功嗰幾個嘅錄影會
落咗磁碟,而 fail-soft 保留咗**舊**快照 —— 錄影新、快照舊。下星期重播就會攞住
半新半舊嘅錄影去對舊快照,爆咗但唔係因為有 bug。

**實測重現過。** 而家錄影期間先入緩衝,成個指標成功先落磁碟,中途掟錯全部丟棄
(`withFixtureTransaction`)。同時逐個指標清 `metaCache` —— 否則一個已回滾嘅
`comp.json` 會經 in-process cache 漏去下一個指標,變成另一個方向嘅 desync。

## 測試流程唔准錄影

R5 嘅突變測試前提係「改壞 transform,錄影唔跟住變」。測試流程任何一條路會觸發錄影,
成個突變測試就係假嘅 —— 改壞咗之後錄影一齊變,永遠對得上,永遠綠燈。

- 錄影**只**由 `npm run fixtures` 同 `npm run refresh` 觸發(兩個都明文設 `HKDM_FIXTURES=record`)
- `test:checks` / `validate` / `build` 全部唔會寫錄影
- R8 每次跑完會核對錄影目錄一個 byte 都冇改
- 驗收方法:`chmod -R a-w src/data/_fixtures` 之後跑 `npm run test:checks`,應該照樣全綠

> 呢一條係撞出嚟嘅:R7(測「交易成功之後錄影真係落磁碟」)最初寫入真嘅錄影目錄,
> 雖然佢自己清返,但目錄設唯讀之後就爆。而家 R7 寫去臨時目錄
> (`HKDM_FIXTURE_DIR` 呢個 seam 就係為咗佢)。

## 錄影檔會有孤兒

錄影檔名由 URL + query 內容決定。改咗登記冊(換 cv code、改 `period_start`)就會
產生一個新檔,舊嗰個冇人再讀但仍然留喺 repo。實測撞過:8 個統計處指標,9 個 POST 錄影。

`npm run fixtures` 會清 —— 但**只有全部指標都成功先清**,否則失敗嗰個嘅錄影
(已回滾、冇被 touch)會連舊版一齊被刪。
