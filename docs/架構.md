# 三層防護 — 邊層防乜

呢個站有三層互相**唔重疊**嘅防護。三層防唔同嘢、喺唔同時候跑、失效方式亦唔同。
混淆咗就會出現「以為驗過,其實冇」。

| 層 | 防乜 | 幾時跑 | 失效之後會點 |
|---|---|---|---|
| **Fixture 重播** | **程式碼**回歸 —— 改壞 transform | 每次 `test:checks`,零網絡 | 改壞咗嘅計算靜靜哋出街 |
| **不變式檢查**<br>(人口 pin、分類相加) | **上游數據**漂移 —— 來源改結構／改口徑 | 每次真實重抓 | 用錯咗嘅行／欄冒充正確數字 |
| **Fail-soft** | **可用性** —— 上游暫時掛咗 | 每次真實重抓 | 個站變空白,或者出空陣列 |

## ⚠️ Fixture **唔**保護上游漂移

呢點唔寫低,遲早有人以為 fixture 綠燈就代表數據啱。

錄影同快照係**一齊更新**嘅(`npm run refresh` 一次過做兩樣)。所以上游改咗結構,
錄影同快照會一齊郁,重播照樣對得上 —— **綠燈,但個數可能已經錯咗**。

抵擋上游漂移嘅係**不變式檢查**,而佢哋只喺真實重抓嗰陣先跑得到:

- 人口:抽出嚟每一點都要等於嗰期「男 + 女」相加
- FSTB / manual:分類相加要等於來源自己印嘅總額
- 統計處:每個 cv code 都要對返 `table_<id>_lang.json` 存唔存在

### 公共經常開支嘅人手輸入與口徑閘(2026-09-08)

`loadManualIndicator()` 另驗 `public_expenditure_policy_groups`：
`category_order` 同各年度 series 必須完全跟 PDF 十組次序(包括 null 骨架)；
已填嘅教育／社會福利／衞生逐項對同年度 FSTB 政府開支快照，先統一百萬元同港元；
每年十組填齊就必須提供 PDF 總額，沿用 **1 百萬元絕對差**，唔用百分比。
缺錨、錯值、錯次序都係 hard fail。七個非錨組別之間交換數值仍可能通過，仍要人手逐行對 PDF。
三年比對唔需要 schema 加 dimensions，亦冇加入 PDF parser。
突變自證用固定嘅三年錨測例，透過臨時檔案行正式 loader；唔依賴會逐年修訂嘅快照。
網站預設仍然只讀目前 repo 嘅政府開支快照，測例唔係缺數時嘅後備。

`scripts/expenditure-scope-gate.mjs` 喺 validate/build 前驗靜態資料引用及本地 import 依賴，
阻止同一頁把政府經常開支同公共經常開支合圖或將總額相加。
首頁係唯一例外：只准載入後逐張卡展示；改普通文案、空白、註解或附件清單唔受影響，
改程式流程就要連同例外及突變測試重新檢視。

呢個係**保守源碼守衛，唔係通用 JavaScript 數據流分析**：
涵蓋 literal FileAttachment、靜態 import 同 literal import()，以及本地依賴；
計算出嚟嘅檔名、fetch 同自行複製數字唔喺範圍內。
同頁兩張獨立圖亦會被擋，目前兩頁各自展示符合呢個限制。
測試用臨時檔案故意合圖、加總、經 helper 混入及改首頁流程，證明真實 production gate 會拒絕。

年度增減只取**同一公共口徑、相鄰且填齊**嘅兩年，用後一年減前一年，唔跨缺數年度。
計算器有增加、減少、不變及前一年度四個已知答案自證，再測 null 同錯口徑。

### 教學換算同引用(2026-09-08)

`test-teaching-anchors.mjs` 用已知答案驗青年勞動人口分母、CPI 百分比算式、
正／負／零變動，以及年度人口分母；源碼突變只喺臨時副本執行，替換必須精確命中一次。
財年由呼叫者明文傳 `fiscal: true`，包括有歧義嘅 2000-01；年度／財年只用同年6月人口，
冇就省略錨點。月度則用不遲過該月嘅年中或年底人口。
CPI 來源係按年率，十二個重疊按年率唔會相乘或開根做成另一個「平均」。

`citation.js` 只讀該頁原始指標，選項唔帶數值；產生文字時按期數、分類重新讀原值，
冇唯一有效值就拒絕，唔把 null 轉成零，亦唔自行加出總額。只有原文件有 `totals` 才提供總額。
公共開支增減引用接原始指標及 `{from, to}`，附兩年原值、狀態同減法算式，
唔接已經減完嘅圖表 series。年度金額引用初始年份跟圖表選擇。

口徑 `basis_zh` 由現有指標登記冊一處維護，三類 API loader 都帶入快照；
例如 GDP 嘅當時市價同失業率嘅勞動人口分母會跟引用一齊離開網站。
`test-citations.mjs` 先對正差、負差、零差同完整小數自證，再以缺值、重複值、
單位不符、錯口徑、缺來源及缺口徑文字等突變驗證。
兩組測試放喺 R8 錄影不變審計之前，唔會順手重錄上游資料。

引用預覽、選取文字同複製全部喺本頁執行；剪貼簿不可用就提供手動複製，
唔送去外部服務。三條學習路線同備忘工作紙係普通靜態頁，
冇答案表單、資料儲存或跨指標收集功能；尚未開工嘅 §12a 另等規格。

## 合規唔等於數啱

Schema 驗證只答「格式啱唔啱」,唔答「個數啱唔啱」。

實測過三個突變:

| 突變 | schema | 對數 |
|---|---|---|
| loader 寫漏 `source_url` | ✗ 捉到 | ✗ 捉到 |
| 人口換算 ×1000 → ×1001 | **✓ 過到** | ✗ 捉到 |
| 失業率 `pin` 由 Total 改成男性 | **✓ 過到** | ✗ 捉到 |

後兩個 schema 完全過到,靠「重播結果嘅 `content_hash` 對返已 commit 嘅快照」先捉到。
所以 `test:checks` 嘅 R5 一定要同時做兩樣:驗 schema **同埋**對數。

## Fail-soft 只覆蓋「攞唔到數」

用 error **類型**分,唔用 message 分(message 係畀人睇嘅,改文案唔應該改變行為)。

```
UpstreamError  網絡去唔到 / HTTP 唔 ok / 回應唔係 JSON / 上游格式變
               -> fail-soft:保留上一版,build 照樣成功,Actions summary 標紅

其餘一切       schema 錯 / cv code 錯 / 換算錯 / 登記冊打錯字
               -> hard fail:下星期再抓一萬次都一樣錯
```

呢個係**白名單**唔係黑名單:新加嘅錯誤類型預設 hard fail,唔會靜靜哋被吞。

## 6 日新鮮期 — 三道閘一齊擋

快照有 6 日新鮮期,期間 `observable build` **完全唔會執行 loader**;
CI 部署用 `HKDM_OFFLINE=1`,更加永遠唔會執行。所以「改壞咗 transform」
單靠 build 係捉唔到嘅 —— 實測過 loader 寫漏 `source_url`,build 綠燈,出緊舊快照。

1. `build` 開頭 `npm run validate` —— 驗現有快照同 `manual/`(零網絡)
2. `test:checks` 用錄影重播完整 transform,再對返快照(零網絡、0.2 秒、11 個指標)
3. schema 錯誤 hard fail,唔行 fail-soft

## 錄影同快照要原子更新

一個指標唔止打一個 endpoint:

| 來源 | 每個指標打幾多個 |
|---|---|
| 統計處 | **3**(`comp.json` + `lang.json` + POST) |
| 庫務署(財政儲備) | **8**(每個財政年度一份檔) |
| FSTB | 1 |

錄影做喺 HTTP 層,所以「頭幾個成功、最後一個 404」嗰陣,成功嗰幾個嘅錄影會
落咗磁碟,而 fail-soft 保留咗**舊**快照 —— 錄影新、快照舊。下星期重播就會攞住
半新半舊嘅錄影去對舊快照,爆咗但唔係因為有 bug。

**實測重現過。** 而家錄影期間先入緩衝,成個指標成功先落磁碟,中途掟錯全部丟棄
(`withFixtureTransaction`)。同時逐個指標清 `metaCache` —— 否則一個已回滾嘅
`comp.json` 會經 in-process cache 漏去下一個指標,變成另一個方向嘅 desync。

## 測試流程唔准錄影

R5 嘅突變測試前提係「改壞 transform,錄影唔跟住變」。測試流程任何一條路會觸發錄影,
成個突變測試就係假嘅 —— 改壞咗之後錄影一齊變,永遠對得上,永遠綠燈。

- 錄影**只**由 `npm run fixtures` 同 `npm run refresh` 觸發(兩個都明文設 `HKDM_FIXTURES=record`)
- `test:checks` / `validate` / `build` 全部唔會寫錄影
- R8 每次跑完會核對錄影目錄一個 byte 都冇改
- 驗收方法:`chmod -R a-w src/data/_fixtures` 之後跑 `npm run test:checks`,應該照樣全綠

> 呢一條係撞出嚟嘅:R7(測「交易成功之後錄影真係落磁碟」)最初寫入真嘅錄影目錄,
> 雖然佢自己清返,但目錄設唯讀之後就爆。而家 R7 寫去臨時目錄
> (`HKDM_FIXTURE_DIR` 呢個 seam 就係為咗佢)。

## 量度工具要自證

**任何新嘅量度工具,出第一個數之前要先對已知答案自證。**

已經有**四次**量度工具本身壞咗:

| # | 工具 | 點壞 | 如果信咗會點 |
|---|---|---|---|
| 1 | shell 突變測試 | heredoc 喺 shell function 入面冇改到檔 | 突變測試假 PASS —— 檢查器根本冇跑過 |
| 2 | R7 原子性測試 | 寫入真嘅錄影目錄 | 唯讀檢查假綠;而且測試自己喺度錄影 |
| 3 | 對比度審計 | regex 當 `oklch()` / `color(srgb …)` 係 0–255 rgb;疊色次序反轉 | **56 個假警報** |
| 4 | 軸標籤量度 | `body` 喺深色主題透明,fallback 寫死白色 | 深色模式全部算成 1.34:1 |

四次都係**工具講嘅嘢同現實唔同**,唔係產品有事。四次都係自己捉返 —— 但唔應該靠彩數。

### 做法

搵三至四個答案已知嘅個案,跑一次,**全中先信個工具**。
自證個案連同預期值寫喺工具旁邊。

對比度審計用嘅四個:

```
黑字白底            = 21
#767676 白底        = 4.54   (WCAG 嘅經典邊界個案)
#777777 白底        = 4.48   (啱啱唔夠 4.5)
白字黑底            = 21
```

`#767676` 同 `#777777` 特別有用:兩個只差一級灰,但一個過一個唔過。
把尺唔夠準就分唔開佢哋。

### 硬規矩

**未自證過嘅量度結果,唔准寫入報告或者 commit message。**

同「檢查器要自證」係同一條道理嘅另一面:
檢查器要證明「整壞嘢佢會嘈」,量度工具要證明「已知答案佢量得啱」。
兩者都係:**冇自證過嘅綠燈,同冇跑過冇分別**。

## 錄影檔會有孤兒

錄影檔名由 URL + query 內容決定。改咗登記冊(換 cv code、改 `period_start`)就會
產生一個新檔,舊嗰個冇人再讀但仍然留喺 repo。實測撞過:8 個統計處指標,9 個 POST 錄影。

`npm run fixtures` 會清 —— 但**只有全部指標都成功先清**,否則失敗嗰個嘅錄影
(已回滾、冇被 touch)會連舊版一齊被刪。
