# 交畀 Claude Code 的分階段指令

## 用法

1. 開一個空 repo，將 `SPEC.md` 放喺根目錄
2. `cd` 入去開 Claude Code
3. 逐步貼落面嘅指令。**一步一步嚟，每步驗收咗先做下一步**
4. 每步完成即刻 commit。出事可以退返轉頭

**唔好做嘅事**：唔好將研究報告成份貼落去。報告係敘述體、有大量背景同權衡討論，Claude Code 會抓錯重點。要 SPEC.md 咁樣嘅陳述式規格。

---

## 第 0 步：探路（最重要，唔好跳）

```
讀晒 SPEC.md。

呢一步唔好寫任何 loader、唔好起任何檔案結構。

SPEC 第 6 節列咗 12 個指標嘅預期資料來源，但啲連結同表號係由研究整理出嚟，未實測過。你嘅任務係逐個實測，然後報告實情。

對每一個來源：
1. 嘗試實際攞一次數據
2. 記錄：實際可用嘅 endpoint / 下載連結、真實回傳格式、一段 sample response、有幾多年歷史、更新頻率、有無繁中欄位
3. 如果攞唔到，講清楚係點解——404？要 cookie？要 JS render？只有 PDF？

輸出一份 findings.md，用表格列晒 12 個來源嘅實測結果，並分三類：
- 可以自動抓（寫得 loader）
- 要人手抄（放 manual/）
- 攞唔到（建議剔除或換來源）

唔好美化結果。攞唔到就直接講攞唔到。
```

**驗收**：你自己抽兩三個 endpoint 出嚟自己開一開，睇下佢講嘅係咪真。呢步係成個專案最容易出事嘅地方——如果 findings.md 有虛構 endpoint，後面全部會爛。

---

## 第 1 步：骨架 + 一個 loader 打通

```
根據 findings.md，揀一個「可以自動抓」入面最簡單嘅指標，做一條完整通路：

1. 起 Observable Framework 專案，按 SPEC 第 4 節嘅目錄結構
2. 寫呢一個指標嘅 data loader，輸出符合 SPEC 第 5 節 schema 嘅 JSON
3. 起一個指標頁，顯示：一個 Plot 圖 + 來源資訊 + 資料表摺疊區
4. 起 index.md，顯示一張指標卡

只做呢一個指標。唔好順手加其他。
```

**驗收**：`npm run build` 出到靜態檔；打開嗰頁見到圖、見到來源連結、見到數據截至日期；斷網再開仍然見到（因為數據已經係靜態）。

---

## 第 2 步：抽出模板

```
而家有一個指標頁行得通。將入面可重用嘅部分抽出嚟：

- components/source-footer.js：接收 indicator JSON，渲染來源／連結／截至日期／授權
- components/indicator-card.js：首頁用嘅卡
- components/anchor.js：對比錨點計算（見 SPEC 第 9 節）
- src/data/_lib/：共用嘅抓取、正規化、schema 驗證函式

加一個 schema 驗證：任何 loader 輸出唔符合 SPEC 第 5 節 schema，build 要 fail 並講清楚邊條欄位有問題。
```

**驗收**：故意整壞一個 loader 嘅輸出（例如刪走 `source_url`），build 要 fail 並準確指出問題。

---

## 第 3 步：擴到全部可自動抓的指標

```
按 findings.md 嘅「可以自動抓」清單，逐個加 loader 同指標頁。

一次做一個，做完一個 commit 一次。唔好一次過寫晒。

每個做完之後，用一句講：呢個指標對應 SPEC 第 1 節邊個活動、建議用邊種圖。
```

**驗收**:每加一個都自己開頁睇一睇圖啱唔啱睇。呢度最容易出嘅錯係圖表類型揀錯（例如人口金字塔畫咗普通長條）。

---

## 第 4 步：人手數據

```
按 findings.md 嘅「要人手抄」清單：

1. 喺 manual/ 為每個指標起一個 JSON，schema 同自動抓嘅一樣，acquisition 設 "manual"
2. 數值留空（留 TODO 標記），我會自己填
3. 寫 manual/README.md，逐個列：去邊度攞、幾時更新、抄邊幾個數、有咩要注意
4. 確保 build 流程會讀 manual/ 嘅 JSON，同自動抓嘅一視同仁

唔好嘗試自動解析 PDF。
```

**驗收**：`manual/README.md` 要具體到你半年後自己睇得明。呢份係年度維護清單。

---

## 第 5 步：自動更新 + 離線

```
1. 寫 .github/workflows/refresh-data.yml：每週一次重跑全部 acquisition 為 "api" 嘅 loader
   - Fail-soft：單個 loader 失敗要保留上一版 JSON，唔好覆蓋或清空
   - 全部失敗 build 仍要成功，但要喺 Actions summary 標紅
   - manual/ 永遠唔碰
   - 無實際變動唔好留空 commit

2. 加 service worker + PWA manifest（見 SPEC 第 8 節）
   - 離線 banner 顯示數據截至日期
   - 報告全部 JSON 加埋幾大
```

**驗收**：手動觸發一次 Actions；再故意將一個 loader 嘅 URL 改壞，睇下係咪真係保留舊數據而唔係清空。呢個 fail-soft 行為唔測過唔可以信。

---

## 第 6 步：部署

```
部署到 Cloudflare Pages（或 GitHub Pages，二揀一）。
寫低部署設定同自訂網域步驟。
```

**驗收**：手機開一次，離線開一次。

## 幾個實際提醒

- **每個 session 開頭叫佢讀 SPEC.md。** Claude Code 唔會自動記得上次講過乜
- **佢寫得太多就叫停。** 呢類專案最常見嘅失敗係一次過生成幾十個檔，之後你唔知邊度出事
- **findings.md 同 manual/README.md 係你嘅資產**，唔係中間產物。半年後要更新數據，睇返呢兩份就夠
- **年度維護節奏**：大部分指標一年更新一次就夠。唔好追每月數，追唔切反而令個站長期顯示「數據截至」好耐之前，比一開始就講明係年度數據更差
