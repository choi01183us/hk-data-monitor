# 新聞、航班及天氣：定時快照與官方即時入口

## 授權及範圍

SPEC 第 2 節要求瀏覽器唔抓外部 API，第 11 節原先唔做即時資料。
2026-09-09 擁有人明確選擇「定時快照＋官方即時入口」。今次只喺伺服器建置／排程階段
取得政府公報、前一日航班及天文台天氣報告；主站仍然零後端、零帳戶、零瀏覽器外部請求及離線優先。
SPEC 本文保持凍結；呢個功能唔係即時追蹤服務。
2026-09-09 擁有人再要求天氣自動配合現時天氣及刪除所有手動選項；沿用上述快照方式。

| 快照 | 官方登記及 API | 本站內容 |
|---|---|---|
| `news` | [新聞處資料集](https://data.gov.hk/tc-data/dataset/hk-isd-gnmis-gnmis)；[繁體 RSS](https://www.info.gov.hk/gia/rss/general_zh.xml)；[官方 XML schema](https://www.isd.gov.hk/datagovhk/press_release_rss.xsd) | 政府新聞公報標題、原文連結、每篇發布時刻 |
| `flights` | [機管局資料集](https://data.gov.hk/tc-data/dataset/aahk-team1-flight-info)；[官方規格](https://www.hongkongairport.com/iwov-resources/misc/opendata/Flight_Information_DataSpec_en.pdf) | 原定日期為香港前一日嘅客機抵港及離港紀錄 |
| `weather` | [本港地區天氣報告](https://data.gov.hk/tc-data/dataset/hk-hko-rss-current-weather-report)；[rhrread JSON](https://data.weather.gov.hk/weatherAPI/opendata/weather.php?dataType=rhrread&lang=tc) | 天氣標記原代碼陣列、報告及標記各自更新時刻 |

資料依 [DATA.GOV.HK 使用條款](https://data.gov.hk/tc/terms-and-conditions)取用，
同頁標明機構、資料集、日期及原文入口，承認香港特區政府／機場管理局知識產權，
並歸功 DATA.GOV.HK。唔聲稱公共領域，亦唔聲稱官方背書。
只使用該站明確開放嘅歷史航班 API；機場一般網站另有
[再分發限制](https://www.hongkongairport.com/tc/terms-of-use.page)，
所以本站唔抓取其即時看板、圖片、標誌或其他網頁內容。
新聞唔收錄全文、圖片、影片或 AI 摘要。

首頁地圖旁沿用 `cityNews()` 的精簡模式，按同一快照次序顯示首四則公報標題；
城市頁維持首七則。兩處共用日期、來源、使用條款、過期提示及官方入口，
英文介面仍清楚標示新聞為中文原文。冇第二份快照、額外抓取或獨立刷新排程。

即時資料只係使用者自行開啟嘅外部連結：
[政府即日公報](https://www.info.gov.hk/gia/general/ctoday.htm)、
[客機抵港](https://www.hongkongairport.com/tc/flights/arrivals/passenger.page)、
[客機離港](https://www.hongkongairport.com/tc/flights/departures/passenger.page)。
航班紀錄唔提供機身座標、航跡、航線流量、準點率或旅客人數。

## 2026-09-09 真實探路發現

新聞 RSS 及機管局 JSON 均以 Node 原生 `fetch` 實際取得 HTTP 200，毋須 API key。
初次部分參數排列／請求遇 403，不能視為永久穩定；沿用既有 HTTP 逾時及有限重試。
唔因一次失敗換成未核實來源。

新聞最重要嘅坑係 channel 時戳：探路見 `lastBuildDate` 停喺 2016 年，
channel `pubDate` 亦帶同香港本地時鐘有矛盾嘅 GMT 標示。
**兩者一律唔用。** 每篇 `item/pubDate` 明文帶 `+0800`，嚴驗時區、曆日同星期後轉 ISO UTC；
網站再顯示香港時間。`updated_at` 係所收公報最新發布時刻；`fetched_at` 係實際成功抓取完成時刻。
原 RSS 只代表政府公報，唔等於全港媒體新聞全集。RSS 內可能包括警方通告、官員講辭及例行公告。

航班請求格式：

```text
https://www.hongkongairport.com/flightinfo-rest/rest/flights/past?date=YYYY-MM-DD&arrival=true&cargo=false&lang=zh_HK
https://www.hongkongairport.com/flightinfo-rest/rest/flights/past?date=YYYY-MM-DD&arrival=false&cargo=false&lang=zh_HK
```

官方登記及規格只承諾每日更新至前一曆日。實測 API 亦回今日／未來資料，
但本站唔依賴契約外嘅即時能力。超出日期範圍實測 HTTP 400；唔改成空陣列。

回應根係日期群陣列，**唔准用 `response[0]` 或全攤平**。查 2026-09-08 可同時見到
鄰日原定日期群，因有跨午夜啟航或提早抵達；貨機探路甚至見到較早兩日群。
本站只選 `date === requested_date`、`arrival` 等於要求方向、`cargo === false` 嘅唯一群。
因此口徑必須寫「原定日期為 YYYY-MM-DD 嘅客機航班紀錄」，唔係該曆日實際升降總數。
API 內容唔足以另造航空交通統計。

- `time` 保留來源時鐘字串；實際啟航／到閘口時間留喺原 `status`，唔猜兩者差額。
- `flight` 陣列係共享航班編號，保留喺同一列，唔拆成多次升降。
- `origin`／`destination` 係 IATA 機場代碼陣列，唔靠記憶加城市名。
- `statusCode: null` 及 `status: ""` 係合法狀態；唔把空白補成「準時」。
- 個別客機 `terminal` 可以空字串；本站冇展示客運大樓、閘口或登記櫃檯。
- `lastUpdatedTime` 帶 `+08:00`，抵離兩回應取較新一個作 `updated_at`；
  另列 `requested_date`，唔把今日來源更新時刻冒充今日航班。
- 要求日期群不存在、重複、空清單或壞欄位一律 `UpstreamError` 保留舊版。
  探路未真實遇到空清單；呢個拒絕策略已用突變測試自證。

## 更新、錄影及失敗處理

`.github/workflows/refresh-city.yml` 保留每三小時（UTC :37）的城市更新，現在每次四個公開請求：新聞一次、
客機抵離各一次、天氣一次。GitHub 排程可能延遲，唔係即時服務保證。原每週統計排程冇改。
兩排程共用 `hkdm-refresh` concurrency group，避免同時推送；成功後沿用既有部署 workflow。
本次只提交排程設定，冇喺使用者電腦安裝常駐服務或啟動外部部署。

天氣另於每小時 UTC :07 執行同一 workflow，透過 `--weather-only` 只抓一次 HKO，
不重抓新聞或航班。兩個 cron 共用原非取消鎖、先測試再提交、部署同一新 SHA。
GitHub 排程可能延遲；來源日期及過期提示先係判斷依據。
正常 build 讀已提交快照；主動更新全部用 `node scripts/refresh-city.mjs`，
只更新天氣用 `node scripts/refresh-city.mjs --weather-only`。
可供離線嘅檔案係 `_city_snapshots/news.json`、`flights.json` 同 `weather.json`，與統計 schema 分開。
`_city_fixtures/news/`／`flights/`／`weather/` 各自只保留最新一次成功回應，唔交畀舊 `record-fixtures` 清理。
日期 URL 每日變化都唔會累積歷史孤兒錄影。

沿用 `_lib/http.js` 的有限重試、`UpstreamError` 及錄影交易。每來源先喺同一磁碟臨時目錄
錄好完整回應，完成轉換／驗證先換入；快照提交失敗會回復舊錄影。
網絡、HTTP 或上游格式問題先可保留上一版；schema、程式、檔案系統錯誤一律 hard fail。
首次抓取失敗而冇舊版亦 hard fail，唔造「無新聞／零航班」嘅空資料。
新聞失敗唔妨礙航班保留／更新，反之亦然；排程 summary 明文標紅保留舊版嘅來源。

內容 hash 包括來源設定、原定日期及全部紀錄，排除抓取／回應更新時刻同暫時 build 提示。
新聞／航班只有抓取或回應時刻變而紀錄內容一樣，原快照與錄影整份保留。
天氣的報告／標記時刻則一併放入 record 作內容：新報告即使天氣標記相同亦要更新，
只有擷取時刻變而兩個來源時刻及標記完全不變才保留原檔。
所以 `fetched_at` 準確代表保存嗰份快照取得時刻，唔聲稱係最近一次檢查時刻。

新聞／航班 loader 可以附 `build.stale` 年齡提示：build 時距快照取得超過六小時，或航班原定日期已非
當時香港前一日，就提示較舊快照。呢個暫時欄位唔寫入原快照，亦唔冒充最近網絡錯誤紀錄。
前端每分鐘按裝置時間重算年齡，離線或長開頁面亦會提示；唔會外部抓數。
使用者仍要按頁上完整日期判斷；即時資訊跟官方入口。

## 解析器與驗證

新聞用已鎖定 Observable Framework 1.13.4 所需嘅 `jsdom` 作 **Node 建置期 XML 解析**。
package 及 lock 冇加新 dependency；瀏覽器唔載入 jsdom。保留 jsdom 預設唔執行腳本、
唔抓外部資源，另拒絕 DOCTYPE／ENTITY、無效 XML、錯來源／語言、重複項目、
非官方安全 HTTPS 連結及元素形式嘅標題。唔另設鬆散 parser fallback。
日後升級 Framework 要重跑呢組 fixture 測試，確認其已安裝建置依賴仍可用。

`scripts/test-city-feeds.mjs` 包括：

- 先以香港／UTC、跨年及閏年四個已知答案自證時間工具，再驗真實時刻。
- RSS CDATA、XML entities、錯時戳、惡意連結、DOCTYPE、截斷、空清單突變。
- 航班鄰日群、抵離、客貨、共享編號、空狀態、null 行及缺欄位突變。
- schema 經重算 hash 仍拒絕錯來源／授權／日期／全文，防止只靠 hash 的假安全。
- 移除香港時差、改讀第一日期群、漏共享編號、移除新聞主機閘、吞程式錯嘅源碼突變。
- 首次缺資料 hard fail、上游失敗舊檔逐 byte 不變、程式錯 hard fail、提交失敗回復錄影，
  以及首個 HTTP 成功但整體失敗時丟棄半套錄影。
- 真實錄影零網絡重播，完整結果及 hash 對返已提交快照，驗完所有原快照／錄影不變。


## 自動天氣：來源與顯示限制

- [官方 API 文件](https://data.weather.gov.hk/weatherAPI/doc/HKO_Open_Data_API_Documentation_tc.pdf)
  的 `rhrread` 是本港地區天氣報告，更新頻率為每小時及當有更新數據時。
  正式 loader 實測 HTTP 200；本輪只取天氣標記，沒有氣溫、雨量或警告推算。
- `updateTime` 是整份報告更新時刻，`iconUpdateTime` 是標記更新時刻，`fetched_at` 是本站擷取。
  本輪真實報告 21:02 仍採用 18:00 標記，唔可以用標記時刻判整份新報告失效。
  三者分開保留，頁面顯示香港時間。
- 29 個原碼及中英文名稱按[官方圖示字典](https://www.hko.gov.hk/textonly/v2/explain/wxicon_c.htm)
  對應本站 CSS 示意。70–77 才明確屬夜間；不以使用者所在地或本機時區估晝夜、月相。
  潮濕不代表雨，冷不代表雪；雷暴以雲景及官方文字表達，不製造閃光或模擬雨勢。
- [天文台多標記說明](https://www.hko.gov.hk/tc/whatsnew/f2_wn20120321e.htm)：
  兩個圖示表示預報時段內的天氣轉變；本站完整保留兩者，停止單一天氣粒子，
  不取第一個或較嚴重一個冒充現況。
- 本站保守顯示規則：報告或擷取超過 90 分鐘、或裝置時鐘落後超過五分鐘，
  特效停止，保留日期及最新官方入口。這不是天文台訂立的資料有效期。
  標記可以比新報告早數小時，不另猜其有效時段。
- 刪除所有手動場景及暫停選項；自動短動畫最多四秒一次，其後保持靜態。
  系統減少動態或列印完全沒有動畫；前端每分鐘只重算年齡，不抓外部或站內資料。
- 標記代碼未知、空陣列、來源時間格式變等為 UpstreamError，有舊快照才可保留；
  最終 schema、程式或磁碟錯誤仍 hard fail。首次無快照失敗不產生假晴天。
- 沿用 DATA.GOV.HK 條款，首頁註明香港天文台及政府版權；效果是本站自製 CSS，
  沒有複製官方天氣圖像或標誌。
